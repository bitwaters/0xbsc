# 全项目代码审查与修复

本轮覆盖全部源码与测试的类型检查、导出引用分析和测试执行；人工审查重点为发现入口、GMGN 调度与字段转换、安全门、试运行状态机、Telegram 发布、SQLite 写队列、归档和结果追踪。目标是修复可复现的问题、合并重复实现，不改变已批准的市场阈值和风险门。

## 已修复的问题

| 级别 | 问题与触发条件 | 修复与定位 | 验证 |
| --- | --- | --- | --- |
| P1 | 消息请求已经发出，但响应缺字段、无法解析，或 API 返回服务端错误时，被当成确定失败并释放防重复锁。可能再次推送同一代币。 | `src/delivery/outbox.ts` 保留 DELIVERY_UNKNOWN 与 token lock；`telegram.ts` 保留 API 错误码。只有确定未发送或明确拒绝才按失败处理。 | 不完整成功响应、异常响应结构、API 500 均保留锁；重复扫描不会二次发送。原有 429 退避和明确拒绝测试通过。 |
| P1 | GMGN 的比例字段错误复用“数值大于 1 则除以 100”的兼容转换。异常值 1.2 会变为 0.012，从而可能通过安全门。 | `src/safety/normalize.ts` 增加严格 ratio 转换；Info、Security、holders 和 creator 的已确认比例字段使用该契约。通用历史百分数转换保留。 | 对 1.01、1.2、20、负数、NaN 拒绝；Info 早筛和实际适配器测试覆盖。修正旧测试中把 holders 比例写成 20/80 的失真样本。 |
| P1 | 停止定时器之后立即关闭数据库；正在运行的发送、确认回调、采集和研究写入仍可能使用已关闭连接，部署退出也可能丢失确认后工作。 | `src/runtime/task-group.ts` 统一跟踪后台 Promise；入口停止新增工作后等待发现、后台任务、确认回调、试运行和研究写入，再关闭 checkpoint/SQLite。Compose 给予 90 秒退出宽限。 | 暂停完成回调时 drain 不会提前完成；回调派生任务也纳入等待；停止发现后不再启动新候选。 |

| P2 | 一批 K 线只要含 CANDLE_GAP 就整批丢弃，导致缺口前已能确定的 TP/SL 也消失。 | `src/research/outcome-collector.ts` 让 firstTouch 按时间顺序判断缺口；其他质量异常仍拒绝，缺口数据不进入完整区间缓存。 | “先触达目标、后缺口”保留 TP；“先缺口、后上涨”维持 UNKNOWN。 |

## 精简

- 将旧版安全检查、发现快照预筛和试运行安全门的阈值映射集中到 `src/safety/thresholds.ts`，消除重复类型声明和配置映射。
- 正式信号与候选诊断的 K 线采集复用一条实现；保留各自的调度预算标记。
- 删除无源码、测试或 CLI 引用的 `currentInfoSwaps`、`resourceExclusion`、`StageStatus`，以及报价决策中已由前置判断覆盖的重复分支。
- 启用 `noUnusedLocals`、`noUnusedParameters`，将无用局部代码检查纳入 CI。
- 保留仍被历史回放、控制组与兼容发布使用的旧策略模块和数据库迁移。没有为降低文件数量删除这些行为。

## 验证

- `npm run ci`：类型检查、ESLint、385 项测试和构建通过。
- `npm audit --omit=dev`：检查时生产依赖已知漏洞为 0；这不构成不存在未知漏洞的证明。
- `git diff --check` 通过。
- 新增 11 项回归测试，并扩展已有发现停机、holders 和比例样本测试。
- 没有迁移本地数据库、修改历史信号价格、删除历史数据或执行真实交易。

## 边界

本轮修复工程正确性与可维护性，不证明新规则已有高命中率。正式筛选阈值、风险硬门、不可变卡片及倍数/下跌统计口径保留。

入口和数据库模块仍较大。下一轮结构调整应按可独立测试的领域抽取，不能把拆文件数量当作质量指标。长期保留全部研究事实与固定存储上限仍存在容量边界；本轮修复重复预留，不通过删除历史或提高上限掩盖容量问题。缺失 K 线、同根蜡烛触及上下界及来源时间未知仍如实标记不确定。

详细运行指标仅保存在本机忽略目录，本文仅包含可公开的代码行为和验证方法。
