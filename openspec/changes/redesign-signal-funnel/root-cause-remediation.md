# 完整漏斗整改：实现与验证契约

本文只描述代码、公开API语义与验证方法。详细运行验收记录保留在本地忽略目录，不随代码发布。

## 根因分类

1. 行情条件和统计风险门可能没有交集。早期风险检查提前返回会遮蔽本已满足行情条件的候选，应分别计算再交叉报告。
2. BSC权限适配误用了Solana mint权限字段。GMGN文档说明该字段在EVM为默认false，不能直接当作BSC拥有增发权限的证据。
3. 首次观察和重复复查共用FIFO，以及请求严格优先级，可能使新候选迟到、结果采集长期得不到服务。
4. 结果采集主要依赖发送成功时，无法评价被拒候选；未闭合K线缓存和逐个追赶错过的轮询又会损害测量。

## 实现边界

| 环节 | 实现 |
| --- | --- |
| 权限与LP | BSC适用EVM所有权和明确权限风险检查；兼容owner字段，未知/冲突拒绝。不伪造mint安全值；其他权限、LP与launchpad例外规则保留 |
| 行情与风险 | 每次Info独立记录模型条件、实际值和阈值；报告行情×Info风险交集，基本安全拒绝不重复计数 |
| 候选调度 | 有上限的工作槽，同币串行；首次观察和复查各自FIFO，两类都等待时按有界比例服务；已激活候选优先 |
| 请求调度 | formal最高优先级；其他请求等待超过界限后按先来先到服务；研究任务仍必须满足健康、并发和独立权重预算 |
| 候选测量 | 首次行情合格时登记token+pool诊断坐标，包含风险拒绝者。固定参考价，有限容量，排除样本单列；不创建正式投递锁或outbox |
| 路径采集 | 等待K线结束再缓存；已有确定TP/SL或不可修复顺序未知时停止对应目标后续轮询；缺段不填补成确定结果 |
| 积压恢复 | 直接捕获最近已到达的观察坐标，记录错过的轮询数；价格路径仍从原始baseline读取，不跳过期间的下跌 |
| 失败记录 | 分别记录排队超时、资源排除、池变化等脱敏原因，不用单一采集失败标签掩盖原因 |

## 规则所有权与效果边界

行情参数仍由版本化model manifest拥有，风险参数仍由riskPolicyHash绑定的配置拥有。本次没有通过任意放宽阈值来保证信号数量。

诱捕/捆绑交易量是统计特征，不能等同于合约honeypot事实。是否将其从正式硬门转为风险分层仍需明确策略选择；未获得该选择前保留原阈值。

`candidate_reference_v1`是参考价诊断，价格来源时钟和可成交性未经验证。便利采样不代表总体命中率，不能与正式卡片或确认后同数量报价结果混算。结果按上涨倍数与下跌先触达分类；观察到期仅决定删失状态，不代替时间收益。

固定预算无法保证整个发现母集都高频复查。长期保存全部高频事实也需要明确容量与保留策略。代码健康不等于质量验证完成，少量样本不能作为策略晋级证明。

## 回归与审查

- BSC正向样例使用真实链字段形态，覆盖owner未知/冲突、明确危险权限及LP不足仍拒绝。
- 风险拒绝者保留行情通过证据，诊断坐标重启后不重定价，诊断不产生正式推送。
- 慢请求并发有上限，同一代币不会获得重复工作槽。
- 首次观察绕过复查积压，持续请求下结果任务不被饿死；研究与正式混合负载仍遵守预算。
- 同根无法排序、缺段及未结束K线不得产生虚假确定结果。
- 跳过过时轮询后完整补采：先跌至0.85倍再涨至1.5倍仍判先触及下跌线。
- 完整工程CI共374项测试通过。生产效果仍需独立数据评价；原提案中未完成的效果验证任务不冒充完成。
