# 零推送全链路根因审查（2026-09-09）

## 结论

当前零推送的直接原因是行情条件与统计风险硬门的交集为空；同时存在独立的BSC权限字段适配错误，会在普通DEX路径继续误拒绝。调度迟到与结果采集缺失使规则效果无法可靠校准。API联通、429、影子开关、Telegram不是当前直接阻断点。不能再用容器healthy、模拟测试通过、扩大观察数量代替业务验收。

## 证据与边界

- 当前应用2a42d96（仓库文档HEAD4f5d5ba）、trial/live、研究off、模型b45519a8、语义efbb4a3e。09:53:47至10:59:27 UTC约65分钟，17,941次API全部200，0次Security/Pool/Traders/Holders/Quote请求，新outbox/SENT均0。1,623个不同代币有Info。P99约334ms、最大895ms、WAL积压0。
- 截至11:01:09，复算9,979份Info、1,654个不同代币。29个代币在47个时点满足全部五项行情激活；47个时点全部因诱捕统计占比>20%拒绝。通过Info早筛的4,560份事实、991个代币中，行情激活通过0。统计量单位是0–1，未发现本批百分比换算造成误拒绝。
- 这991个代币中，仅21个曾满足流动性>=30,000、18个曾满足1分钟量>=2,000；它们不是同一时点的联合通过。去掉一个行情条件也几乎不能改变空交集。说明不是简单把某一个市场参数放宽10%就能解决。
- 历史约15.8小时共132,730份Info复算：90个不同代币、2,707个时点满足行情激活；2,631次首先受诱捕门阻断（76个不同代币），36次通过Info早筛（12个代币）。去掉诱捕门后仍有捆绑、creator缺失等独立阻断；不能只删掉一个if便宣称解决全部漏斗。
- 历史Security共2,353份：renounced_mint全部false；is_renounced为true的2,335份。GMGN官方说明renounced_mint是Solana字段，在EVM为默认false。现代码permission-gate无条件要求mintDisabled=true，gmgn-adapter又把renounced_mint直接赋给它。近同期179组Info/Security中，普通DEX56组因此拒绝；正确跳过不适用的Solana字段后，19组通过权限/LP子门，37组仍被LP门拒绝，另7组所有权未通过。这里仅检验权限子门，不代表完整安全或正式发送通过。
- 正向测试把BSC的renounced_mint模拟为true，未覆盖真实链语义；这是此前数百项测试仍漏掉业务阻断的具体原因。
- 当前候选最长等待约160秒。50个名额外的FIFO解决公平性但不能同时解决时效。高频发现冷币不应反复占用与新活跃候选相同的取数预算。发现速度、实际首次Info延迟、激活后的复查延迟必须分别验收。
- 部分DATA_WAIT实际上是有完整零交易数据、行情已FAIL、重复内容导致后续窗口UNKNOWN，requiredFacts为空；不能把这些统计作API缺字段。
- 历史首次激活按token+pool有92个坐标，其中24个后续被采样到>=1.3倍、8个>=2倍。但价格采样最长间隔中位数约29分钟，不足以可靠判定TP/SL先后，更不能用于声称高命中率。简单移除诱捕门的55个首次坐标中，33个后来采样到<=0.9倍；不能用“让更多币通过”冒充质量优化。
- 未发候选没有对等、连续的独立结果采集；当前结果追踪主要由SENT触发。零推送又导致零新结果，形成无法学习的闭环。这是研究设计缺口。

## 一次性整改边界

1. 统一风险契约，明确链适用性。BSC用EVM字段核验所有权/权限、可卖性、合约风险及LP；Solana字段标不适用，不伪造为安全true。真实未知与明确风险分别记录。
2. 行情筛选与风险评估独立记账：先记录每项行情条件的实际值、通过状态和风险交集，再决定是否准备。不能因早筛提前return而让报告显示没有市场机会。
3. 分离合约事实底线与预测型统计特征。20%诱捕等经验硬门需作为策略决策重新审议；它不是honeypot检测。任何转为分层/提示或改变阈值都会扩大正式推送范围，应明示版本与影响，不暗中绕开安全门。
4. 调度围绕新机会时效：冷候选退避，发生实质新活动可唤醒；新候选与复查分预算，在预算内优先及时检查有新活动者；保留未知候选公平探索配额。不要继续增大FIFO容量来假装解决延迟。
5. 不依赖发送成功的独立候选结果采集：固定首次决策坐标，按1.3/1.5/2/3倍与0.9倍的先触达分类，缺段/同根无法排序单独未知。有限容量、共享20权重调度、保存选择概率和未采样原因；报告不能用幸存者样本计算总体命中率。
6. 验收从“单测+healthy”改为真实BSC契约样例、历史点时回放、当前规则交集、调度时效、完整准备/发送链与缺失率。模拟传输通过只证明工程链路，正式样本不足不宣称效果已验证。

上述整改应形成同一套规则/字段/调度/测量契约后统一Review及部署。不能把统计硬门直接调高后依旧沿用“高质量已验证”的表述。

审查范围：发现→排队→Info契约→行情/风险→权限/LP→深度准备→报价/出站→Telegram→结果采集。

1. 直接零推送阻断已由实际API记录、逐事实独立复算定位，不能用后续门从未被执行推断它们已在真实行情全部通过。
2. 修复测试失真：BSC正向fixture改为renounced_mint=false，并验证owner未知/矛盾、危险权限与LP不足仍拒绝。

4. 有界并发测试覆盖慢请求、3槽上限、同币再次到期不重复处理、完成后释放槽位。服务退出等待全部工作结束。
